# GDB stack — cclib/cql (libcql.a) + cql/gdb + gdbscripts

> Facts in `domain/facts.md` apply. **gdb = global database** (mmap
> read-only snapshot), never a debugger. Changing `cclib/cql` has a
> wide blast radius: `libcql.a` is linked by `cql/siodsgi`,
> `util/ccidb` (gdbbin/dbbin tools) and many other directories.

## cclib/cql — data model (read before changing)

Files of one GDB directory (structs in `include/gidx.h`,
`include/_disk.h`): `DATA` (concatenated patient data, one segment per
patient), `usgidx` (ghead header + `gidx_rec{pid,index}[]` global
index), `gidx` (per-patient `patrec`: offset/size + 5 sidecar file
slots EDIT/LOG/ADTREC/DBVAR/AUDIT), `PATS` (patient master table),
`LOG`, `adtRec`, `AUDIT`, `Fgindex.<it>` (per-item index; fancy items
carry `.envno`; generated by makeitidx after a build). Flags separate
`GDB_FLAG_NORMAL` (online ActivePatients) from `GDB_FLAG_ARCH`
(archived `ArchGDB_*`; search path from ccResources
`globaldb/gdbdirs`).

## Exposure path and call chain

This layer registers no Scheme primitives itself — `cclib/cqlA/gccidb.c`
wraps it (`ccigDbOpen` → `GNdbopen`, ...) and `cclib/cqlA/cci.c`
`init_ccisubrs()` registers them as `gdb-*`. Full chain:
`(gdb-open)` → `ccigDbOpen` → `GNdbopen` (Ndbopen [prebuilt libccidb]
+ mopen mmap + reading usgidx/PATS) → `flocons(dbtd)`;
`(gdb-step)` → `ccigDbStep` → `_ggdbmi` (binary-search index → mmap
DATA reads → DBI → `MakegDbiList` assembles the Scheme table).

## Change + verification

- `cd cclib/cql && make` → relink consumers (`cql/siodsgi`,
  `util/ccidb`; grep Makefiles whose `CCLIBS` contain `cql`). Touching
  headers like `include/gidx.h` → full-tree make is safer.
- Verification canaries: `gdbbin/dbck`; rebuild a small store with
  `gdbscripts/GDBBUILD`; `cql -igdb_table_dump.scm` before/after dump
  diff must be identical. **Verify only against test-site data.**
- Performance: reads are mmap end-to-end (`mio.c`); index selection in
  `gdbdef.c` `gbestidxlist`.

## cql/gdb — maintenance .scm + GUI queries

Installs default to `$CCRUN/cql`; `gui_*` files go to `$CCRUN/gdbcql`
via `$(SCRTn).INSTALLDIR := $(GDBCQLDIR)`. `Makefile`: new entries
continue from `SCRT50`.

.scm maintenance scripts (installed to `$CCRUN/cql`, run via
`cql -i<script>`):

- `ccarch.scm`: infrastructure for the archive ledger
  `$CCSYSDIR/ccarch` (`arch-*` accessors, `get-init-arch-index`,
  `gdbbuild-logfile` = `$CCRUN/log/gdbbuild.log`).
- `buildcurrentgdb.scm` / `buildlastmongdb.scm`: current/previous-month
  archive GDB build (first `$CCRUN/gdbbin/checkdisk max` for disk
  headroom; limited by `GDBbuildlimit` in `StatusConfig`).
- `checkcurrentgdb.scm` / `checkgdbarhdir.scm`: consistency checks.
- `getoldgdb.scm`: find the oldest `ArchGDB_*` (called by ROLLLASTGDB).
- `movegdb.scm`: per-patient GDB migration (env `GDBCURRENT`/`GDBNEW`).
- `gdb_util.scm`: traversal tools (`gdb-for-all-patients` via
  `gdb-patient-def/next/undef`).
- `gdb_table_dump.scm` + `gdb_table_util.scm`: bulk table export per
  `$CCSYSDIR/cql/gdb_table.cf`.
- `dumpallcpa.scm`: per-patient `cpaDumpPaths`.
- `odbc.scm` / `odbc2.scm` / `odbc_util.scm`: **cql as an ODBC data
  source backend** (`\x04`-delimited pipe protocol; launched by
  `links/odbc/odbc.c` as `cql -b -iodbc.scm`; datatype constants in
  `gui_comm.scm` must stay in sync with the ODBC side).

gui_* extension-less files (Scheme source, installed to
`$CCRUN/gdbcql`): consumed by the Motif program `cqlg` in
`tools/gdb_gui/uimx/` (`getFilenames` enumerates `gui_`-prefixed files
as menu entries). `gui_define.scm` defines the protocol
(`gui-gen-command`); `gui_<topic>_Queries` are the query sessions
(opening the store named by `$GDBCURRENT`). Adding a GUI query = add a
`gui_Xxx` file + Makefile SCRT entry + INSTALLDIR `GDBCQLDIR`. Note
`gui_Care_Path` is commented out / not installed.

## gdbscripts — production GDB ops ksh (legacy)

**Not part of the current build** — only `Makefile.OLD` exists (historic
install target `$CCRUN/gdbbin`); the root Makefile collection does not
pick it up, and scripts ship via release packages / manual
distribution. Changes here do NOT take effect via `make install` —
mind the delivery method (fact 6 / pack red line).

Scripts (ksh; if installed, in `$CCRUN/gdbbin`): `GDB` (GUI query
entry: sets `GDBCURRENT=$CCSYSDIR/gdb/ActivePatients` then
`.dosu $CCSYSUTIL/cqlg $CCRUN/bin/cql $CCRUN/gdbcql ...`),
`GDBBUILD <gdb path>` (copy_dbs to `.BUILDTMPDIR` + makeitidx, then
atomic replace), `NLGDBBUILD` (near-line store:
`cql -i$CCRUN/cql/buildcurrentgdb.scm`), `MOVELASTGDB`/`ROLLLASTGDB`
(monthly rolling; disk over `GDBbuildlimit` [StatusConfig, default
80%] refuses, writes `$CCRUN/log/gdbbuild.log` + mail; ROLLLASTGDB
finds the oldest ArchGDB via `cql -b -igetoldgdb.scm`),
`STARTHOLDGDB` (gdbbuild -hold), `checkdisk` (largest free disk per
ccResources `globaldb.disks`), `find_existing_disks`, `premove*`,
`gdb_link_all`, `copy_gdb_templates*`, `runGDBdemo`, `GDB.remote`.

These scripts orchestrate the C tools in `util/ccidb/Makefile` and
`cclib/cql/` (build engine `gdbbuild.c`, index `gdbmakeitidx.c`) and
the .scm in `cql/gdb/`. Behavior changes normally belong in the .scm/C
layers, not here.
